# 新規デザインシステム作成

`design-principles` スキルの「モード 1: 新規作成」を実行する。

## 実行内容

1. design-principles スキルを読み込む
2. **前提条件のヒアリング**: リポジトリ内の既存情報を確認し、推測できない項目をユーザーに質問する
3. UI の方向性を決める（オブジェクト指向 UI かタスク指向 UI か）
4. 該当するサービス種別を選ぶ（管理画面、社内向けツール、SaaS、toC）
5. UI の方向性 → 特化ルール → 原則 → WCAG の順でルールを適用する
6. DESIGN.md を作成する

**ルールへのフィードバック**: 対話中にルールの改善点が見つかった場合、ユーザーに伝え、`docs/design-principles/` への編集を提案する。正本は `docs/design-principles/`（スキルの `references/` はそこへのシンボリックリンク）。

## 成果物

次を含む DESIGN.md：

- プロダクトの UI の方向性（オブジェクト指向 UI かタスク指向 UI か）と選択理由
- 画面領域ごとの UI の方向性（一つのプロダクトに両方の画面があるときは領域ごとに書く）
- 画面領域ごとのサービス種別（管理画面、社内向けツール、SaaS、toC）
- 採用したルール（優先順位順）
- トークン名とコンポーネント名の対応
- 必須ルールを外した項目がある場合、その理由
