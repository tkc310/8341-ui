# モード 3: 評価・レビュー（画面 / デザインの評価）

`design-principles` スキルの本体（[SKILL.md](./SKILL.md)）でヒアリングを終え、このモードを選んだときに読む。

**目的**: 既存の画面デザインやモックアップをレビューする。ルール違反を見つけ、改善提案をする。

## 読む順序

1. レビュー対象の画面
2. `references/README.md` - 評価基準の優先順位
3. `references/ui-orientation.md` - チェックリストで方向性が適切か確認する
4. 画面の目的に合う特化ルールだけ（`references/services/` から）
5. `references/principles.md` の、対象に当てはまる適用ルールの節だけ
6. `references/wcag-for-designers.md` の必須項目

## レポートの構成

### 0. UI の方向性の適合性

- **現在の方向性**: オブジェクト指向 UI かタスク指向 UI か
- **判断**: ドメインと対象ユーザーに照らして適切か
- **チェックリスト結果**: `ui-orientation.md` のチェックリストに沿った確認結果
- **提案**: 方向性の変更が必要な場合、理由とともに

### 1. WCAG 必須違反

達成基準を満たさない項目。必ず修正が必要。

- **項目**: 該当する達成基準（例: 1.4.3 コントラスト（最低限））
- **問題**: 何がどう基準を満たしていないか
- **修正方法**: 具体的な改善案

### 2. 必須ルール違反

UI の方向性、特化ルール、または原則の必須を満たさない項目。修正が必要（外す場合は理由を明記）。

- **項目**: 該当するルール（例: 原則「操作の幾何」）
- **問題**: どのルールに反しているか
- **修正方法**: 具体的な改善案

### 3. 推奨からの提案

推奨ルールに沿った改善提案。プロダクトの方針に応じて採用を検討する。

- **項目**: 該当するルール
- **提案**: より良くするための提案
- **根拠**: なぜその提案が有効か
