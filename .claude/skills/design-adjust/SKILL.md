# 既存デザインシステム調整

`design-principles` スキルの「モード 2: 既存の調整」を実行する。

## 実行内容

1. design-principles スキルを読み込む
2. **前提条件のヒアリング**: 既存の DESIGN.md とリポジトリ内の情報を確認し、変更点や追加の制約をユーザーに質問する
3. UI の方向性が適切か確認する（ドメインと対象ユーザーが変わった場合は見直す）
4. 調整が必要な領域に関係するルールを参照する
5. トークンやコンポーネントの追加・変更を行う
6. DESIGN.md を更新する

**ルールへのフィードバック**: 対話中にルールの改善点が見つかった場合、ユーザーに伝え、`docs/design-principles/` への編集を提案する。正本は `docs/design-principles/`（スキルの `references/` はそこへのシンボリックリンク）。

## 成果物

- UI の方向性の確認結果（変更がある場合は新しい方向性と理由）
- 追加・変更したトークンとコンポーネントの定義
- 必須ルールを外した場合の理由の追記
- 既存ルールとの整合性確認結果
