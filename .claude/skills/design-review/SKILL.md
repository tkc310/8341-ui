# デザインレビュー

`design-principles` スキルの「モード 3: 評価・レビュー」を実行する。

## 実行内容

1. design-principles スキルを読み込む
2. **前提条件のヒアリング**: レビュー対象（範囲、懸念点）、既存の DESIGN.md、期待するアウトプットをユーザーに確認する
3. レビュー対象の画面を確認する（Figma URL、スクリーンショット、コードなど）
4. UI の方向性が適切か確認する（オブジェクト指向 UI かタスク指向 UI か）
5. 画面の目的に合うルールを参照する（UI の方向性 → 特化ルール → 原則 → WCAG）
6. ルール違反と改善提案を抽出する
7. レビューレポートを作成する

**ルールへのフィードバック**: 対話中にルールの改善点が見つかった場合、ユーザーに伝え、`docs/design-principles/` への編集を提案する。正本は `docs/design-principles/`（スキルの `references/` はそこへのシンボリックリンク）。

## レポート構成

### 0. UI の方向性の適合性

画面の方向性が適切か確認する。

- 現在の方向性: オブジェクト指向 UI かタスク指向 UI か
- 判断: ドメインと対象ユーザーに照らして、現在の方向性が適切か
- チェックリスト結果: ui-orientation.md のチェックリストに沿った確認結果
- 提案: 方向性の変更が必要な場合、理由とともに提案する

### 1. WCAG 必須違反

達成基準を満たさない項目。必ず修正が必要。

- 項目: 該当する達成基準
- 問題: 何がどう基準を満たしていないか
- 修正方法: 具体的な改善案

### 2. 必須ルール違反

UI の方向性、特化ルール、または原則の必須を満たさない項目。

- 項目: 該当するルール
- 問題: どのルールに反しているか
- 修正方法: 具体的な改善案

### 3. 推奨からの提案

推奨ルールに沿った改善提案。

- 項目: 該当するルール
- 提案: より良くするための提案
- 根拠: なぜその提案が有効か

## レビュー時の追加確認

レビュー時には次の観点も確認する：

- コメントが日本語かどうか
- 不具合になりそうな部分はないか
- リファクタできそうな部分がないか（変更差分の範囲内のみ）
- 修正が必要な場合は提案のみ行い、修正は実行しないこと
- インラインコメントやPRコメントで補足した方が良い箇所がないか

（フロントエンドの場合）
- 不必要なメモ化（useMemo/useCallback）がないか
- 過剰な抽象化によって可読性が低下していないか
- リンクは next/link を利用しているか
