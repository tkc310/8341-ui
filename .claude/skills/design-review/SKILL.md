# デザインレビュー

`design-principles` スキルの「モード 3: 評価・レビュー」を直接呼ぶ入口。

1. `../design-principles/SKILL.md` を読み、手順 1（前提条件のヒアリング）でレビュー対象（範囲・懸念点）、既存の DESIGN.md、期待するアウトプットを確認する
2. レビュー対象の画面を確認する（Figma URL、スクリーンショット、コードなど）
3. `../design-principles/mode-3-review.md` を読み、対象に当てはまる `references/` だけを読む
4. ルール違反と改善提案を抽出し、mode-3-review.md の「レポートの構成」で報告する

ルールのギャップに気づいたら `../design-principles/feedback.md` の手順でユーザーに伝える。

## レビュー時の追加確認

- コメントが日本語かどうか
- 不具合になりそうな部分はないか
- リファクタできそうな部分がないか（変更差分の範囲内のみ）
- 修正が必要な場合は提案のみ行い、修正は実行しないこと
- インラインコメントや PR コメントで補足した方が良い箇所がないか

（フロントエンドの場合）

- 不必要なメモ化（useMemo / useCallback）がないか
- 過剰な抽象化によって可読性が低下していないか
- リンクは next/link を利用しているか
