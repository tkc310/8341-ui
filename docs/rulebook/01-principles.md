# 01 デザイン原則

8341-ui は、画面設計のルールとして [design-principles](../design-principles/README.md)（`docs/design-principles/`）を採用する。
この章は、design-principles のルールのどれを、8341-ui のどのトークンとコンポーネントで満たしているかの対応表と、8341-ui 自身の設計方針を置く。
ルールの本文は `docs/design-principles/` を正とし、ここには写さない。

## 適用の順序

design-principles のルールは、次の順で適用する。後のルールは、前のルールが書いていない判断にだけ使う。

1. **UI の方向性**（オブジェクト指向 UI かタスク指向 UI か）
2. **サービス別の特化ルール**（管理画面、社内向けツール、SaaS、toC）
3. **ウェブデザインの原則**（15 の適用ルール）
4. **WCAG 2.2 の達成基準**（必須はどの段階からも緩めない）

8341-ui は複数のプロダクトで共有する基盤なので、1 と 2 は決めない。
UI の方向性とサービス種別は、8341-ui を使う各プロダクトの DESIGN.md で決める（雛形: [`templates/PRODUCT-DESIGN.md`](../../templates/PRODUCT-DESIGN.md)）。
8341-ui が受け持つのは 3 と 4 であり、どのサービス種別でも組み立てられる部品とトークンを用意する。

| 読み順と優先度     | 見出しの段ごとのテキストスタイル（`text.heading-*`）、Heading の `level` と `size` の分離、primary ボタンは 1 画面 1 つの規約                                                                             | 画面ごとの強調要素の選定                                           |

## 特化ルールへの備え

各サービス種別の「トークン」節に挙がるものを、基盤として用意しているかの対応。

| サービス種別          | design-principles が求めるトークン・部品                                                 | 8341-ui                                                                       |
| --------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 管理画面              | 表の行高、等幅の識別子、状態色（成功・警告・危険・中立）、危険操作のボタン | `text.dense-*`、`text.mono-*`、Tag の tone、Button `danger`。Table はバックログ |
| 社内向けツール / SaaS | 状態色、フォームの規約、空状態                                             | FormField 一式、NotificationBanner。空状態の部品はバックログ                    |
| toC                   | 主操作のサイズ、本文幅、危険操作                                           | Button `lg`（52px）、`size.prose-max`（720px）、Button `danger`                 |

design-principles は、題材と無関係に「同じ角丸と薄い影のカードを敷き詰める」見た目を避けるよう求めている。
Card は情報のまとまりを示す部品であり、表の行の代わりに並べない（[04 コンポーネント](./04-components.md) の「部品の選び方」）。

## 必須ルールを外した項目

なし。design-principles の必須より厳しくしている項目は次のとおり。

| 項目                     | design-principles                    | 8341-ui                       |
| ------------------------ | ----------------------- | ------------------------------- |
| タップ領域               | 24 CSS px 以上（2.5.8） | 44 CSS px 以上                  |
| 大きい文字のコントラスト | 3:1 以上                | 文字はサイズによらず 4.5:1 以上 |
| リンクの下線             | 推奨                    | 必須                            |
| フォーカス表示の線       | 推奨（3:1 の線）        | 必須（明暗二重の線）            |

## 8341-ui の設計方針

design-principles のルールとは別に、このシステム自体を作るときの方針を置く。

1. **少ない選択肢で組む**: トークンとバリエーションを意図的に絞る。新しい値やバリアントを足す前に、既存の組み合わせで解決できないか検討し、足すときは ADR を書く。
2. **ネイティブ要素を優先する**: `button`、`a`、`details`、`select`、`fieldset` の振る舞いを使い、独自の操作体系を作らない。
3. **測って、直す**: 品質は検証できる基準で守り、見つけた問題はチェックかテストを足して再発を防ぐ（[06 改善ループ](./06-improvement-loop.md)）。
4. **ルールへ返す**: design-principles にギャップや曖昧さを見つけたら、8341-ui の中で例外を作らず、`docs/design-principles/` を直す PR を出す（`design-principles` スキルの「ルールへのフィードバック」）。プロダクト固有の例外は、そのプロダクトの DESIGN.md に書く。

### 見た目の性格

キーカラーは **藍（hue 265）**。装飾は控えめにし、情報を主役にする。

| 性格 | 具体的には                                             |
| ---- | ------------------------------------------------------ |
| 静か | 影は 3 段階のみ。面の差は背景色と罫線で表す            |
| 明快 | 太字は 700 の 1 種類のみ。中間ウェイトを使わない       |
| 誠実 | 状態は必ず文字でも示す。動きは状態変化の説明にだけ使う |
