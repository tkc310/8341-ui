# 01 デザイン原則

判断に迷ったときに立ち返る 5 つの原則です。番号が小さいほど優先します。

## 1. 誰も取り残さない

障害の有無、年齢、端末、通信環境、言語の習熟度にかかわらず、同じ情報と操作に到達できること。
アクセシビリティは後から足す品質ではなく、最初から満たす前提条件として扱います。

- 色・形・位置のどれか 1 つだけに意味を持たせない
- キーボードだけで、また画面読み上げだけで、すべての操作が完了できる
- 文字を 200% に拡大しても、横幅 320px でも、情報が欠けない

## 2. 迷わせない

見た目と振る舞いを一貫させ、利用者が学習したことを裏切らない。

- 同じ意味のものは同じ見た目、違う意味のものは違う見た目にする
- 1 画面の主要な操作（primary ボタン）は 1 つを目安にする
- ネイティブ HTML 要素の振る舞い（`details`、`select`、`fieldset`）を優先し、独自の操作体系を作らない

## 3. 文字で伝える

UI の大部分は文字。装飾よりも、読みやすさと言葉の正確さに投資する。

- 本文 16px・行間 1.7、1 行 40〜45 字（`size.prose-max`）を基準にする
- アイコンは文字の補助。単独で使うのは、閉じるボタンなど慣習が確立したものに限る
- エラーは「何が起きたか」と「どうすればよいか」を書く（[05 文言](./05-writing.md)）

## 4. 少ない選択肢で組む

トークンとバリエーションを意図的に絞り、組み合わせで表現する。選択肢が少ないほど、誰が作っても揃う。

- レイアウトの余白は 3 段階（8 / 24 / 64px）、ブレークポイントは 1 点（768px）
- 新しい値やバリアントを足す前に、既存の組み合わせで解決できないか検討する
- 足すときは理由を ADR に残す

## 5. 測って、直す

主観ではなく検証できる基準で品質を守り、見つけた問題は仕組みで再発を防ぐ。

- コントラスト、トークン違反、DESIGN.md の同期は CI が機械的に検査する
- 一度起きた問題は、チェックスクリプトかテストを足して二度と起きないようにする
- 改善の記録は [改善ログ](../improvement/log.md) に残す（[06 改善ループ](./06-improvement-loop.md)）

## 見た目の性格

キーカラーは **藍（hue 265）**。落ち着きと信頼感を基調に、装飾は控えめにして情報を主役にします。

| 性格 | 具体的には |
| --- | --- |
| 静か | 影は最小限（3 段階）。面の差は背景色と罫線で表す |
| 明快 | 太字は 700 の 1 種類のみ。中間ウェイトを使わない |
| 誠実 | 状態は必ず文字でも示す。アニメーションは状態変化の説明にだけ使う |
