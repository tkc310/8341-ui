# サービス別の特化ルール

画面の目的が次の四つに当たるときは、このディレクトリのルールを、[ウェブデザインの原則](../principles.md) より先に適用する。特化ルールと原則が同じ判断で食い違うときは、特化ルールを採る。原則は、特化ルールが書いていない判断にだけ使う。

WCAG の達成基準は、特化ルールからも原則からも緩めない。数値と例外は [wcag-for-designers.md](../wcag-for-designers.md) に従う。特化ルールが達成基準より厳しい指定をしているときは、特化ルールを採る。

## どの文書を使うか

一つのプロダクトが複数の種類の画面を持つときは、プロダクト全体ではなく画面ごとに選ぶ。

| 画面 | 文書 |
| --- | --- |
| レコードを繰り返し検索・更新・監査する | [管理画面](./admin.md) |
| 自社の社員が、自分の業務手続きを完了する。顧客には開かない | [社内向けツール](./internal.md) |
| 契約した組織が、継続して日常業務に使う | [SaaS](./saas.md) |
| 個人が、自分のために使う | [toCサービス](./consumer.md) |

管理画面の条件を満たす画面は、SaaS や toC の製品の中にあっても [管理画面](./admin.md) を使う。社内向けと SaaS が同時に当たりそうなときは、主利用者が自社社員だけなら社内向け、契約組織の利用者なら SaaS とする。

## 視覚の決め方

特化ルールの見た目は、題材、主利用者、その画面の主タスクから決める。どのサービスにも同じ配色や同じカードを当てない。

次の見た目は、題材から選んだ結果である場合にだけ使う。題材が空いているから埋める用途では使わない。出典は、画面を題材ごとに区別するための指針（[frontend-design](https://github.com/anthropics/claude-code/blob/main/plugins/frontend-design/skills/frontend-design/SKILL.md)）で、生成されがちな既定として挙げられているものである。

- 生成りの背景に、セリフの大見出しとテラコッタ系のアクセント
- 黒に近い背景に、蛍光色のアクセントを一つだけ置く
- 新聞紙面のようなヘアラインと、角を立てた密集した段組
- 中身の種類と無関係に、同じ角丸と同じ薄い影のカードを敷き詰める
- 見出しの上に必ず付く大文字のラベル、中黒でつないだメタ情報、矢印をすべてのボタンに付ける

大胆にしてよい箇所は、画面につき一つにする。それ以外は静かにする。自動で再生する動きは、注意を引く理由があるときだけ使う。操作の結果を示す動きは使ってよい。
