# 管理画面

運用担当者が、同じ種類のレコードを繰り返し検索し、更新し、例外を処理し、誰が何をしたかを追う画面に使う。SaaS や toC の製品に含まれる管理画面も、この文書を優先する。

主タスクは、目的のレコードへ早く到達し、必要な項目だけを確実に変え、誤更新を戻せることにある。初見の印象や世界観の演出は、この画面の仕事ではない。

## 原則のどこを上書きするか

| 原則のルール | 管理画面での扱い |
| --- | --- |
| 読み順と優先度 | ヒーローや Z 字の配置は使わない。視線の起点は、ページ名、絞り込み、表の見出し、である |
| 一度に出す数 | データの行数には適用しない。減らす対象は、同時に押せる操作である |
| 削る | 主タスクに必要な列、状態、更新日時は残す。飾りの削除と、データの削除を分けない |
| 短い経路 | 推奨ではなく必須にする。絞り込みの保存、一括操作、キーボードを用意する |
| まとまり、判別、配置、文言、状態、誤り、再認、一貫性、助けの場所 | 原則どおり。特化ルールが数値や配置を指定しているときは、特化ルールを採る |

## 必須

- 画面の上部に、対象の種類（注文、利用者、請求）と、今見ている範囲（絞り込み結果の件数）を書く。
- 一覧には、識別子、状態、最終更新、主操作を置く。識別子は等幅で揃え、状態は色だけにしない。
- 絞り込み、並べ替え、ページ分割を、一覧の一部として同じ位置に置く。絞り込み条件は、結果の上に残し、外せるようにする。
- 行の主操作は一つに絞る。破壊的な操作は、行の中に主操作と並べず、確認を挟む。
- 一括操作は、選択した件数を表示してから実行する。対象がゼロのときは実行できない状態にする。
- 作成と編集は、一覧から離れても、戻ったときに直前の絞り込みとスクロール位置が残るようにする。
- 権限がない操作は、隠すか、押せない理由を同じ場所に書く。押したあとに初めて権限エラーを出さない。
- 更新者、更新日時、変更前後が追える項目は、詳細から辿れるようにする。
- 空の結果は、「データが無い」「条件に一致しない」「権限がない」を別の文面にする。
- ポインタの対象は 24 CSS ピクセル四方以上とする。行内の補助操作がそれより小さいときは、[WCAG 2.5.8](../wcag-for-designers.md) の間隔の例外を満たす。

## 推奨

- 頻繁に使う絞り込みは、名前を付けて保存できるようにする。
- 表の数値は桁を揃える。
- 長い表では、見出し行をスクロールしても見えるようにする。
- 詳細は、一覧を置き換えるページか、一覧を残したまま開くペインのどちらかに統一する。画面ごとに混ぜない。

## 見た目

題材は業務データである。配色は、背景、文字、境界、状態（成功、警告、危険、中立）の役割に限る。アクセント色は、主操作と現在地にだけ使う。

書体は UI 用のサンセリフを一つにする。識別子と数値に限って等幅を使ってよい。大見出し用の別書体は置かない。

レイアウトは、上に範囲と絞り込み、下に表または詳細、という縦の順にする。同じ角丸のカードを行の代わりに敷き詰めない。カードを使うのは、レコードが表の列に収まらないときだけにする。

動きは、保存完了、行の追加と削除、ペインの開閉に限る。画面を開くたびに要素を順に浮かび上がらせない。

## 文言

- ボタンは業務の動詞にする。「更新する」「利用停止にする」。完了の通知は、同じ動詞の完了形にする。
- 列名は、運用担当者が台帳で使う語にする。データベースの列名をそのまま出さない。
- エラーは、どの項目が、どの規則に反したかを書く。謝罪の文で埋めない。

## レビュー

- [ ] ページ名、件数、絞り込み、表の順で辿れるか
- [ ] 主操作が行につき一つで、破壊的操作が確認を挟むか
- [ ] 絞り込みを外したあとに、同じ範囲へ戻れるか
- [ ] 空の理由が三種類で書き分けられているか
- [ ] 監査に必要な更新者と日時が辿れるか
- [ ] 飾りのカードや、画面入場の連続した動きが無いか

## トークン

表の行高、セルの左右余白、状態色、危険操作のボタン、数値用の等幅、絞り込みバーの高さ。状態色はコントラストの組として登録する。
