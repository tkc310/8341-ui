# ウェブデザインの原則

この文書は、ウェブの画面（ページ、コンポーネント、フォーム、画面遷移）を設計するときの原則を二つに分けて置く。

前半は、デザイン時の判断が重複しない適用ルールである。一つの判断は一つのルールにだけ置く。各ルールに、後半のどの出典から採ったかを書く。後半は出典のカタログである。枠組みの中身と、適用ルールのどこへ吸収したかを示す。チェックリストは前半にだけ置く。

対象は画面上の配置、見た目、操作、文言、状態表示に限る。紙面、パッケージ、空間のデザインは扱わない。利用者調査や試作を回す手順も、画面に落ちるルールではないのでカタログに出典として残すだけにする。コントラスト比やターゲットサイズなどの達成基準の数値と例外は [wcag-for-designers.md](./wcag-for-designers.md) に置く。使いやすさの選択がその基準と衝突するときは、基準のほうを優先する。これはデジタル庁のガイドブックが「アクセシビリティファースト」と呼ぶ基盤と同じ立場である。

管理画面、社内向けツール、SaaS、toC の画面では、[サービス別の特化ルール](./services/README.md) がこの適用ルールより優先する。特化ルールと食い違う判断は、特化ルールを採る。

## 適用ルール

判断の対象は次のとおりである。

| ルール | 決めること |
| --- | --- |
| 読み順と優先度 | どれを先に気づかせ、どの順で読ませるか |
| まとまり | 同一画面の中で、どれとどれを一つのグループに見せるか |
| 文字と図の判別 | 文字と、情報を伝える図が判別できるか |
| 配置の秩序 | 位置が基準線に乗り、画面の視覚的な重さが極端に偏らないか |
| 操作の幾何 | 押せるものの大きさと、隣との距離 |
| 一度に出す数 | 同時に選ばせる個数 |
| 一貫性 | 画面をまたいで同じ機能を同じものに見せるか。ウェブで広く使われている配置を崩さないか |
| 状態と応答 | 今何が起きているか。待ちが長いか |
| 誤りと撤回 | 失敗を防ぐか。失敗の内容と戻り方を示すか。操作を中断できるか |
| 再認 | 思い出させず、見せて選ばせるか |
| 文言 | ラベルと文が、操作の結果と入力の意味を言うか |
| 削る | その画面の主タスクに不要な要素を置かないか |
| 助けの場所 | ヘルプと検索を、サイト内の同じ場所に置くか |
| 短い経路 | 繰り返す操作に、より短い別経路があるか |
| 自律的な処理の範囲 | 人の操作を待たずに進む処理の境界が分かるか |

### 読み順と優先度

画面の中で、どれを先に気づかせ、そのあとどの順で読ませるかを決める。本文が読める最小の大きさは「文字と図の判別」で決める。見出しを本文より大きくして先に読ませる差は、このルールで決める。

**必須**

- その画面で最初に伝える要素を、サイズ、位置、色のいずれかで他より先に気づく状態にする。
- 見出しの段（大見出し、中見出し、小見出し）ごとに、見た目の差を付ける。同じ段には同じ見た目を使う。
- 一つだけ強調する要素は、周囲と違う見た目にする。強調は画面につき少数にとどめる。

**推奨**

- リストでは、覚えてほしい項目を先頭か末尾に置く。中央に埋もれる配置にしない。

- 文章が主体のページでは、重要事項を左上と見出しの近くに置く。Nielsen Norman Group のアイトラッキングでは、ウェブの文章を読む視線がページ上部と左寄りに集中し、F 字に近い軌跡になることが報告されている。
- 要素の少ないランディングページでは、ロゴを左上、主要なボタンを視線の終端（右上または右下）に置く配置が経験則として使われる。この配置は F 字パターンと同じ種類の計測結果ではない。

**出典**: 階層、フォン・レストルフ効果、連続位置効果、F 字型パターン、Z 字型パターン、情報提示の原則「気づきやすくする」

**レビュー**

- [ ] 画面を開いた直後に目に入る要素が、先に伝えるつもりのものか
- [ ] 見出しの段が、見た目で区別できるか
- [ ] 下位の要素が、上位より目立っていないか
- [ ] リストの重要項目が、先頭か末尾にあるか

**トークン**: 見出しと本文のサイズ差（`fontSize`）、太さ（`fontWeight`）、強調色。強調色と背景の組は「文字と図の判別」のコントラストを満たす。

### まとまり

同一画面の中で、どれとどれを一つのグループに見せるかを決める。画面をまたいで同じ機能を同じ見た目にする判断は「一貫性」に置く。グループを共通の基準線に乗せる判断は「配置の秩序」に置く。

**必須**

- 関係する要素（ラベルと入力欄、見出しと本文）の間隔を、関係しない要素の間隔より狭くする。
- グループの境は、余白、枠、背景のいずれかか、その組み合わせで分かるようにする。
- 同じグループに属する要素は、色、形、サイズを揃える。違うグループは、そのいずれかで区別する。
- 手順や時系列は、線や並びに沿って一つの連なりに見えるようにする。

**推奨**

- グループ内の間隔とグループ間の間隔に、はっきりした差を付ける。

**出典**: 近接、余白（グループ間の間隔）、ゲシュタルトの近接・類同・共通地域・連続

**レビュー**

- [ ] 見出しが、前の節ではなく、続く本文に近い位置にあるか
- [ ] 関係する項目が、一つの塊に見えるか
- [ ] 塊の境が、余白、枠、背景で分かるか
- [ ] 似た見た目の要素が、意図しない一つのグループに見えていないか

**トークン**: グループ内とグループ間の間隔（`spacing.stack.tight` と `spacing.stack.loose` など）。カードの内側余白と背景。

### 文字と図の判別

文字と、情報を伝える図が判別できるかを決める。比率の数値と例外は [wcag-for-designers.md](./wcag-for-designers.md) の 1.4.3 と 1.4.11 に従う。

**必須**

- 通常サイズの文字と背景のコントラスト比は 4.5:1 以上、大きい文字は 3:1 以上にする。プレースホルダーも文字である。
- 情報を伝えるアイコン、グラフ、入力欄の境界と、隣接する色とのコントラスト比は 3:1 以上にする。
- 色だけで状態や系列を区別しない。形、ラベル、パターンのいずれかを併用する。
- 本文の文字サイズと行間は、デザインシステムに一つの初期値として定め、画面ごとに縮めない。
- コンテナの内側には余白を置き、文字が枠に接触しないようにする。

**推奨**

- 長い本文の行間は、文字サイズの 1.5 倍前後にする。WCAG 1.4.12 は、利用者がこの値まで広げても内容が欠けないことを求めている。
- 本文に使う書体は、画面内で少数に絞る。
- 1 行が長く続き、行を見失う組版を避ける。

**出典**: コントラスト、タイポグラフィ、余白（行間とコンテナ内）、情報提示の原則「区別しやすくする」

**レビュー**

- [ ] 文字と背景の組が、上記の比を満たすか
- [ ] アイコンと入力欄の境界が、隣接色から判別できるか
- [ ] 色を取り除いても、状態と系列が分かるか
- [ ] 行間とコンテナ内余白が足りているか

**トークン**: 背景色と文字色の組、意味ごとの色（`color.status.error` など）。組はコントラストを確認してから登録する。`lineHeight`、`padding`、`fontSize`、`fontFamily`。

### 配置の秩序

要素の位置が共通の基準線に乗るか、画面の左右で視覚的な重さが極端に偏らないかを決める。間隔でグループを作る判断は「まとまり」、読む順序は「読み順と優先度」である。

**必須**

- 関係する要素群を、左、中央、右のいずれかの基準線で揃える。
- 列の幅と列間は、画面内で同じグリッドに乗せる。
- 主内容と副内容を並べるとき、幅の比を画面内で一定にする。

**推奨**

- 一つの画面で、揃えの基準を途中で変えない。
- 濃い色や大きい図を片側に置くときは、反対側の余白か文字量で釣り合いを取る。

**出典**: 整列、バランス

**レビュー**

- [ ] 左端、右端、中心が、意図した基準線に乗っているか
- [ ] グリッドから外れる要素が、外す理由のないまま残っていないか
- [ ] 画面の片側だけに、濃い色や大きい図が集中していないか

**トークン**: カラム数、ガター、マージン、コンテンツ最大幅。

### 操作の幾何

押せるものの大きさと、隣の操作対象との距離を決める。個数は「一度に出す数」、達成基準の例外は [wcag-for-designers.md](./wcag-for-designers.md) の 2.5.8 に従う。

フィッツの法則では、ポインタが対象に到達する時間は、対象までの距離が長いほど、対象の幅が狭いほど増える。

**必須**

- ポインタで操作する対象は、一辺 24 CSS ピクセル以上にする。満たさない対象は、各対象のバウンディングボックスの中心に置いた直径 24 CSS ピクセルの円が、他の対象やその円と交差しない位置に置く。
- 同じ画面で続けて押す操作は、直前に操作する要素（入力欄、選択した行など）の近くに置く。

**推奨**

- 主要なボタンは 24 CSS ピクセルより大きくする。Level AAA の 2.5.5 は 44 CSS ピクセル四方である。

**出典**: フィッツの法則、WCAG 2.5.8

**レビュー**

- [ ] ボタン、リンク、アイコンボタンが 24 CSS ピクセル四方以上か
- [ ] それより小さい対象の円が、隣の対象と交差していないか
- [ ] 続けて押す操作が、直前に操作する要素から離れていないか

**トークン**: ボタンの最小サイズ、アイコンボタンのヒット領域、操作対象の間隔。

### 一度に出す数

一つの決定の場に、同時に並べる選択肢の数を決める。思い出させず見せるかどうかは「再認」、不要な説明を削るかは「削る」である。

ヒックの法則では、選択肢が増えるほど、選ぶまでの時間は増える。ミラーの 1956 年の論文が述べたのは、短期記憶が一度に保持するまとまりの数がおおよそ 7 前後だという主張である。メニュー項目を 7 個までにする、という規則そのものは論文の結論ではない。ウェブでは、一度に見せる項目を少数のまとまりに分けるための目安として使う。

**必須**

- 一つの決定に、画面いっぱいの並列選択肢を出さない。分類、段階的な開示、既定値のいずれかで個数を減らす。
- 長い一覧は、見出し、ページ分割、絞り込みのいずれかでまとまりに分ける。

**推奨**

- グローバルナビゲーションの項目は、ひと目で辿れる個数にとどめる。

**出典**: ヒックの法則、ミラーの法則

**レビュー**

- [ ] 一つの決定に、分類されていない選択肢が並んでいないか
- [ ] 長い一覧に、まとまりか絞り込みがあるか
- [ ] 既定値で、選ばなくて済む項目を減らせるか

**トークン**: ナビゲーション項目数の上限、リストのページサイズ、メニューの段数。

### 一貫性

画面をまたいで、同じ機能を同じ見た目、同じ位置、同じラベルにするかを決める。あわせて、ウェブで広く使われている配置を崩さないかを決める。一つの画面の中で似た見た目をグループに見せる判断は「まとまり」である。ラベルの文面が意味を伝えるかは「文言」である。

**必須**

- 保存、取消、削除のように同じ機能のボタンは、全画面で同じ見た目とラベルにする。
- 色の意味（リンク、エラー、成功）を画面ごとに変えない。
- ナビゲーションの位置と項目の順を、全ページで変えない。
- ロゴの位置、戻る操作、主要なメニューの置き方は、他のウェブサイトで広く使われている配置から外れる理由があるときだけ変える。利用者は他サイトで過ごす時間のほうが長く、そちらの配置を前提に操作する、という観察がジャコブの法則と呼ばれる。

**推奨**

- アイコンの描き方（線か塗りか）をサイト内で揃える。
- 日付、金額、状態の表記を揃える。

**出典**: 一貫性、ニールセン「一貫性と標準化」、ジャコブの法則、情報提示の原則「内部一貫性及び外部一貫性を保つ」

**レビュー**

- [ ] 同じ機能のボタンが、画面によって違う見た目やラベルになっていないか
- [ ] 色の意味が画面ごとに変わっていないか
- [ ] ナビゲーションの位置と順序が全ページで同じか
- [ ] 広く使われている配置を外す箇所に、外す理由があるか

**トークン**: 意味ごとの色、ボタンのバリアント、ナビゲーションの部品。

### 状態と応答

今何が起きているかと、応答までの待ちをどう見せるかを決める。失敗したときの文面と戻り方は「誤りと撤回」である。

ドハティのしきい値は、対話の応答がおおよそ 400 ミリ秒を超えると作業のテンポが落ちる、という呼び方で参照される。Doherty と Thadani の応答時間に関する議論に由来する。

**必須**

- 操作を受け付けたこと、処理中であること、完了または失敗したことを、それぞれ画面に表示する。
- 応答がすぐ終わらない処理には、待っていることが分かる表示を出す。
- ナビゲーションでは、現在のページがどこかを表示する。
- 自動で動くカルーセルや通知は、利用者が止められるようにする。条件は [wcag-for-designers.md](./wcag-for-designers.md) の 2.2.2 に従う。

**推奨**

- 400 ミリ秒を超える処理は、完了を待たせず進捗を見せる。

**出典**: ニールセン「システム状態の可視化」、ドハティのしきい値、対話の原則「自己記述性」

**レビュー**

- [ ] 処理中であることが分かるか
- [ ] 操作が受け付けられたことが分かるか
- [ ] 現在のページ位置が分かるか
- [ ] 自動で動く要素を止められるか

**トークン**: 進捗、トースト、スケルトン、現在地を示すナビゲーションの状態。

### 誤りと撤回

失敗を防ぐか、失敗の内容と戻り方を示すか、操作を中断できるかを決める。エラー文の書き方は「文言」に置き、確認を挟む時点と戻し方はこのルールに置く。

**必須**

- 削除や送信など取り消せない操作の前に、内容を確認する段階を置く。
- 入力の形式と制約（必須か、文字数、使える文字）を、入力する前に示す。
- エラーが起きた項目と、利用者が自分で直せる方法を示す。番号だけのエラーにしない。
- モーダルと複数段の入力には、閉じる、中断する、下書きを残すのいずれかを置く。
- 時間制限を置く場合は、解除、調整、延長のいずれかを利用者ができるようにする。条件と例外は [wcag-for-designers.md](./wcag-for-designers.md) の 2.2.1 に従う。

**推奨**

- 入力の誤りは、送信を待たずに、その欄を離れた時点で知らせる。入力の途中では知らせない。
- 元に戻す操作を、破壊的な処理に付ける。
- 入力が揃うまで送信ボタンを押せない状態にして、不足を知らせる代わりにしない。押せない部品はコントラストの基準の対象外で読みにくく、なぜ押せないかも伝わらない。ボタンは押せる状態にしておき、押したときに不足している項目と直し方を示す。

**出典**: ニールセン「エラーの予防」「エラーからの回復」「ユーザーの主導権と自由」、対話の原則「制御可能性」「使用エラーへの耐性」「学習性」

**レビュー**

- [ ] 取り消せない操作の前に確認があるか
- [ ] 入力の形式と制約が、入力する前に分かるか
- [ ] エラーの項目と直し方が分かるか
- [ ] 途中で閉じて、再開できるか
- [ ] 送信ボタンを押せない状態にして、不足の理由を隠していないか

**トークン**: 確認ダイアログ、フィールドのエラー状態、下書き保存。

### 再認

次の操作に必要な情報を、記憶から取り出させず、画面に出して選ばせるかを決める。出す個数は「一度に出す数」である。

**必須**

- 入力値の候補があるときは、自由入力だけにせず候補を出す。
- 直前までに入力した値を、後の段で再入力させない。セキュリティ上必要な再入力と、無効になった値は除く。
- アイコンだけの操作には、ラベルかツールチップで名前を添える。

**出典**: ニールセン「記憶に頼らないデザイン」、WCAG 3.3.7

**レビュー**

- [ ] 選択肢が、記憶ではなく一覧から選べるか
- [ ] 前の段で入れた値を、後の段で打ち直させていないか
- [ ] アイコンの意味が、ラベルかツールチップで分かるか

**トークン**: コンボボックス、入力履歴、ツールチップ。

### 文言

ラベル、リンク、エラー文、見出しが、操作の結果と入力の意味を言うかを決める。同じ機能に同じ語を使うかは「一貫性」である。

**必須**

- ボタンとリンクのラベルに、移動先か動作が入るようにする。「こちら」「詳細」「もっと見る」だけにしない。
- 入力欄には、何を入れるかのラベルを付ける。形式の指定（日付の並びなど）は、エラーのあとではなく前に書く。
- エラー文には、何が違うかと、どう直すかを書く。
- 利用者の作業用語を使い、画面の実装用語をラベルに出さない。

**推奨**

- 略語は、初出で言い換える。

**出典**: 明確さ、ニールセン「実世界とシステムの一致」、情報提示の原則「解釈しやすくする」「簡潔にする」、WCAG 2.4.4 と 3.3.2

**レビュー**

- [ ] ボタンを押したあとに何が起きるか、ラベルから分かるか
- [ ] 「こちら」だけのリンクが残っていないか
- [ ] 入力欄にラベルがあるか
- [ ] エラー文に直し方があるか

**トークン**: ボタンラベルを必須にするコンポーネントの契約。エラー文の定型。

### 削る

その画面の主タスクに不要な要素を置かないかを決める。選択肢の個数は「一度に出す数」、残した要素の文言は「文言」である。

**必須**

- その画面の主タスク（利用者がその画面で終えたい作業）に使わない装飾、説明、動く要素を置かない。
- 主タスクを遮るポップアップは、利用者の判断が要る場合（未保存の変更の破棄など）に限る。それ以外の通知は、主タスクを遮らない位置に出す。
- 自動で再生・移動する要素は、主タスクの妨げになる場合は初期状態で動かさない。

**出典**: ニールセン「最小限で美しいデザイン」、情報提示の原則「注意を逸らさないようにする」「簡潔にする」、対話の原則「タスクへの適合性」

**レビュー**

- [ ] 各要素が、その画面の主タスクに必要か
- [ ] 動く要素や通知が、主タスクから注意をずらしていないか
- [ ] スクロールしないと見えない場所に、主タスクの完了手段が隠れていないか

**トークン**: 画面テンプレートごとの必須領域と、置いてよい補助領域。

### 助けの場所

行き詰まったときに開くヘルプ、検索、問い合わせを、サイト内のどこに置くかを決める。

**必須**

- ヘルプ、検索、問い合わせを置くときは、全ページで同じ位置に置く。WCAG 3.2.6 が求めるのは、ほかの要素に対する相対的な順序を変えないことである。
- ヘルプの項目は、操作の名前で探せるようにする。
- 目的のページへ到達する手段を、ナビゲーション以外にもう一つ置く。検索、サイトマップ、一覧のいずれでもよい。手続きの途中の段や、手続きの結果として表示するページは除く。手段の組み合わせは [wcag-for-designers.md](./wcag-for-designers.md) の 2.4.5 に従う。

**出典**: ニールセン「ヘルプとドキュメント」、WCAG 3.2.6 と 2.4.5、対話の原則「エンゲージメント」のうち、目的までの手がかりを隠さないこと

**レビュー**

- [ ] ヘルプか検索が、全ページの同じ位置にあるか
- [ ] ページを見つける手段が二つ以上あるか
- [ ] ヘルプが、操作名で探せるか

**トークン**: ヘッダーのヘルプと検索の位置。

### 短い経路

同じ操作を繰り返す人に、より短い別経路があるかを決める。初心者が見る基本の経路は残す。

**必須**

- 基本の経路（ボタンを順に押す）を残したうえで、繰り返す操作にショートカット、一括操作、検索のいずれかがある。
- キーボードだけで基本の経路を完了できるようにする。詳細は [wcag-for-designers.md](./wcag-for-designers.md) の 2.1.1 に従う。

**出典**: ニールセン「柔軟性と効率性」

**レビュー**

- [ ] 繰り返す操作に、一括処理かショートカットがあるか
- [ ] 短い経路を知らなくても、基本の経路で完了できるか

**トークン**: ショートカットの一覧、一括操作バー。

### 自律的な処理の範囲

人の明示的な操作を待たずに、画面が判断、生成、推薦を進めるときの境界を決める。そのような処理がない画面では、このルールは使わない。デジタル庁の「人間中心の原則」は、自律性の高いシステムについての配慮として書かれている。人間中心設計のプロセス（調査、試作、評価の回し方）は、このルールに含めない。

**必須**

- 自動で進んだ処理について、何を根拠に何をしたかを画面上で示す。
- 利用者が止められる地点と、結果を取り消せる地点を置く。
- 人とシステムのどちらが最終決定を持つかを、その画面に書く。

**出典**: デジタル庁「人間中心の原則」（自律性の高いシステムに限る）

**レビュー**

- [ ] 自動で起きた処理の内容が分かるか
- [ ] 止める、取り消す、人の判断に戻す、のいずれかがあるか
- [ ] 最終決定が人にあるのかシステムにあるのかが書いてあるか

**トークン**: 生成結果の表示、取り消し、確定前の確認。

カタログは枠組みの内容を残すためのものである。適用時のルールとチェックは前半を使う。

### ビジュアルデザインの基本原則

ウェブの画面とデザインシステム向けに、このリポジトリで選んだ九つである。「デザインの9原則」という標準の一覧があるわけではない。書籍『デザイン9×9』は、比率、空間、バランス、色の属性、テクスチャー、形と形態、動き、リズム、書体という別の九つを使う。そちらの内容はここでは要約しない。

| 原則 | 吸収先 |
| --- | --- |
| 階層 | 読み順と優先度 |
| コントラスト | 文字と図の判別 |
| 整列 | 配置の秩序 |
| 近接 | まとまり |
| 余白 | まとまり（グループ間）、文字と図の判別（行間とコンテナ内） |
| タイポグラフィ | 文字と図の判別 |
| 一貫性 | 一貫性 |
| バランス | 配置の秩序 |
| 明確さ | 文言 |

### ニールセンのユーザビリティ 10 原則

Jakob Nielsen がインタラクティブシステムの評価用に整理した十のヒューリスティックである。原文は [10 Usability Heuristics for User Interface Design](https://www.nngroup.com/articles/ten-usability-heuristics/)（Nielsen Norman Group）。

| 原則 | 吸収先 |
| --- | --- |
| システム状態の可視化 | 状態と応答 |
| 実世界とシステムの一致 | 文言 |
| ユーザーの主導権と自由 | 誤りと撤回 |
| 一貫性と標準化 | 一貫性 |
| エラーの予防 | 誤りと撤回 |
| 記憶に頼らないデザイン | 再認 |
| 柔軟性と効率性 | 短い経路 |
| 最小限で美しいデザイン | 削る |
| エラーからの回復をサポート | 誤りと撤回 |
| ヘルプとドキュメント | 助けの場所 |

### 操作と選択の法則

| 法則 | 内容 | 吸収先 |
| --- | --- | --- |
| フィッツの法則 | 対象までの距離が長く、対象の幅が狭いほど、到達に時間がかかる（Paul Fitts, 1954） | 操作の幾何 |
| ヒックの法則 | 選択肢が増えるほど、選ぶまでの時間が伸びる（Hick–Hyman law） | 一度に出す数 |
| ミラーの法則 | 短期記憶が一度に保持するまとまりはおおよそ 7 前後、という 1956 年の主張。メニュー個数の上限そのものは、この論文の結論ではない | 一度に出す数 |

### デジタル庁のユーザビリティデザインの原則

デジタル庁の DS-671.1『ユーザビリティ導入ガイドブック』は、次の四つを推奨している。アクセシビリティファーストを基盤にし、その上に対話、情報提示、人間中心を置く、という関係である。公開先は [サービスデザイン（デジタル庁）](https://www.digital.go.jp/policies/servicedesign)。対話の原則は JIS Z 8520、情報提示の原則は JIS Z 8522 を参照している。

アクセシビリティファーストは、使いやすさの選択が多様な利用者の利用可能性と衝突したときに、利用可能性を優先するという基盤である。適用ルールの一項目にはせず、この文書の前提にした。数値は [wcag-for-designers.md](./wcag-for-designers.md) に置く。

対話の原則（利用者がシステムとやり取りするときの条件）:

| 項目 | 吸収先 |
| --- | --- |
| タスクへの適合性 | 削る |
| 自己記述性 | 状態と応答 |
| 期待への一致 | 一貫性 |
| 学習性 | 誤りと撤回 |
| 制御可能性 | 誤りと撤回 |
| 使用エラーへの耐性 | 誤りと撤回 |
| エンゲージメントのうち、目的までの手がかりを隠さないこと | 助けの場所 |

情報提示の原則:

| 項目 | 吸収先 |
| --- | --- |
| 気づきやすくする | 読み順と優先度 |
| 注意を逸らさないようにする | 削る |
| 区別しやすくする | 文字と図の判別 |
| 解釈しやすくする | 文言 |
| 簡潔にする | 削る（情報量）、文言（リンクの具体さ） |
| 内部一貫性及び外部一貫性を保つ | 一貫性 |

人間中心の原則は、ガイドブックでは自律性の高いシステム（判断、生成、推薦を人の操作なしに進めるもの）について、透明性、役割分担、制御可能性、データの妥当性を求めている。画面に出る部分は「自律的な処理の範囲」に置いた。利用者の状況を調べ、試作し、評価する人間中心設計の手順は画面ルールではないので、適用ルールには入れていない。

### ゲシュタルトの法則

要素がまとまって見える条件についての視覚の法則である。ウェブのグループ化に使う四つだけを載せる。閉合や図と地は、このカタログには入れていない。

| 法則 | 内容 | 吸収先 |
| --- | --- | --- |
| 近接 | 近い要素は一つのグループに見える | まとまり |
| 類同 | 色、形、サイズが似た要素は一つのグループに見える | まとまり |
| 共通地域 | 枠や背景で囲まれた要素は一つのグループに見える | まとまり |
| 連続 | 線や並びに沿った要素は一つの連なりに見える | まとまり |

### 視線のパターン

| パターン | 内容 | 吸収先 |
| --- | --- | --- |
| F 字型パターン | 文章が主体のウェブページでは、視線が上部と左寄りに集中する。Nielsen Norman Group のアイトラッキングに基づく（[F-Shaped Pattern of Reading on the Web](https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content/)） | 読み順と優先度 |
| Z 字型パターン | 要素の少ないページで、左上、右上、左下、右下の順に要素を置く配置の経験則。F 字型パターンと同じ種類の計測結果ではない | 読み順と優先度 |

### その他のウェブで使う法則

| 法則 | 内容 | 吸収先 |
| --- | --- | --- |
| ジャコブの法則 | 利用者は他のサイトにいる時間のほうが長く、そちらの慣習どおりに動くことを期待する（[Jakob's Law](https://www.nngroup.com/articles/jakobs-law-internet-ux/)、Nielsen Norman Group） | 一貫性 |
| 連続位置効果 | 並びの先頭と末尾の項目が、中央より記憶に残りやすい | 読み順と優先度 |
| フォン・レストルフ効果 | 周囲と違う一つの要素が記憶に残りやすい | 読み順と優先度 |
| ドハティのしきい値 | 応答がおおよそ 400 ミリ秒を超えると、対話のテンポが落ちる、という呼び方。Doherty と Thadani の応答時間に関する議論に由来する | 状態と応答 |
