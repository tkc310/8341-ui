# ジャコブの法則（要約）

- 原文: [Jakob's Law of the Internet User Experience](https://jakobnielsenphd.substack.com/p/jakobs-law)（Jakob Nielsen）
- 確認日: 2026-10-19
- 使っている箇所: [principles.md](../principles.md)「その他のウェブで使う法則」
- 経緯: 以前のリンク先（Nielsen Norman Group の記事 https://www.nngroup.com/articles/jakobs-law-internet-ux/ ）が 2026-10-19 に読めなかったため、Nielsen 本人による解説に差し替えた

## 法則

利用者は、ほかのサイトで多くの時間を過ごしている。そのため、自分のサイトもほかのサイトと同じように動くことを期待する（Nielsen が 2000 年に提唱）。

## 理由

利用者は 1 つのサイトにとどまらず、何度も目にする共通のパターンから「ウェブとはこう動くもの」というメンタルモデルを作り、初めてのサイトにも当てはめる。モデルに合う設計は使いやすく、外れる設計は誤操作と苛立ちを生む。魅力的なサイトでも、覚え直しの負担を上回るのは難しい。

## 設計への示唆

- **既定は慣習に従う**: 上部の検索欄、カートのアイコン、標準のスクロール、ピンチでの拡大、目立つ主操作のボタンなど
- **目新しさのための変更をしない**: スクロールの挙動を乗っ取る（スクロールジャック）、ロゴを中央に置く、などは使いやすさを損なう例として挙げられている
- **大きく良くなるときだけ新しくする**: 少し違うだけでは覚え直しの負担に見合わない。1 割良くなっても 2 割苛立たせるなら失敗する
- **新しい操作方法は収束を待つ**: 音声・AR / VR・AI などでは、競合する設計が共通のパターンに落ち着くのを見て、それに合わせる
- **古い慣習は慎重に捨てる**: 昔の技術の制約から生まれた慣習で、新しいやり方に明らかな利点があるときだけ捨てる
- 標準の部品と振る舞いをできるだけ使い、プラットフォームをまたいでも一貫させる
