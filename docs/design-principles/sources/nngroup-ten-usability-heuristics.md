# ニールセンのユーザビリティ 10 原則（要約）

- 原文: [10 Usability Heuristics for User Interface Design](https://www.nngroup.com/articles/ten-usability-heuristics/)（Jakob Nielsen、Nielsen Norman Group）
- 確認日: 2026-10-19
- 使っている箇所: [principles.md](../principles.md)「ニールセンのユーザビリティ 10 原則」

## 位置づけ

具体的なガイドラインではなく、画面を評価するときの大まかな経験則（ヒューリスティック）。1990 年に Rolf Molich と共にヒューリスティック評価のために作り、1994 年に整理した。中身は 1994 年からほぼ変わらず、2020 年に言い回しを見直している。

## 10 の原則

| # | 原則 | 要点 |
| --- | --- | --- |
| 1 | システムの状態を見えるようにする | 何が起きているかを、適切なタイミングのフィードバックで伝える。結果を伴う操作の前に、今の状態がわかるようにする |
| 2 | システムと現実を一致させる | 内部の用語ではなく利用者が知っている言葉と概念を使い、自然で論理的な順に並べる |
| 3 | 利用者に制御と自由を与える | 誤って始めた操作から抜けられる道（取り消し・やり直し・キャンセル）をはっきり示す |
| 4 | 一貫性と標準 | 製品の中で用語と操作をそろえ、プラットフォームや業界の慣習にも合わせる |
| 5 | エラーを防ぐ | 起きやすい条件を取り除くか、危険な操作の前に確認を求めて、問題を起こさない |
| 6 | 記憶より認識 | 選択肢と情報を見える場所に置き、画面をまたいで覚えておかなくて済むようにする |
| 7 | 柔軟性と効率 | 慣れた人向けの近道を用意しつつ、初めての人の邪魔をしない。よく使う操作は利用者が調整できる |
| 8 | 美的で最小限のデザイン | 関係の薄い情報や滅多に使わない情報を削る。余計な要素は大事な情報と注意を奪い合う |
| 9 | エラーを認識・診断・回復できるようにする | エラーは平易な言葉で、何が問題でどう直せばよいかを示し、気づきやすい見た目にする |
| 10 | ヘルプと文書 | 説明なしで使えるのが理想。必要なときは、探しやすく、作業に沿い、短く、その場で見られるようにする |
