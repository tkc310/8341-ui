## サービスデザインのページ

利用者中心（人間中心）を原則に行政サービスを設計し、年齢・障害の有無・経済状況などにかかわらず、誰もがデジタル化の恩恵を受けられるようにする。デジタルに不慣れな人や、直接サービスを使わない人も含めて、利用者の目的・環境・ライフステージの変化を具体的に想定する。

主な取り組み:

- 行政職員向けに、利用者視点が要る理由・事例・道具をまとめた資料（行政サービスにおける利用者視点導入ガイドブック）
- 政府のウェブサービスの UI の調査・点検と、各府省庁が参照するガイドライン・チェックリスト
- サービスデザインのガイドラインの策定・改定（生成 AI などの新しい論点も含める）
- デザインとウェブアクセシビリティの専門人材による、設計段階からの参画とレビュー
- デザインシステム（β 版）の構築と、デザインデータの公開

## ユーザビリティデザインの 4 つの原則（DS-671.1）

アクセシビリティファーストを基盤にし、その上に対話・情報提示・人間中心の原則を置く。

### 1. アクセシビリティファースト（基盤）

多様な利用者が使えることを最優先にする。使いやすさとアクセシビリティが食い違うときは、アクセシビリティを優先する。JIS X 8341 シリーズや WCAG を参照し、代わりの手段や合理的配慮も含める。

### 2. 対話の原則（JIS Z 8520）

利用者とシステムのやり取りを安全で円滑にする 7 項目。

| 項目 | 要点 |
| --- | --- |
| タスクへの適合性 | 利用者の目的に合い、必要な情報を適切な形で示す |
| 自己記述性 | システムの状態と、次にできることが伝わる |
| 期待への一致 | 利用者の予想や慣れに沿って振る舞う |
| 学習性 | 安全に試しながら使い方を覚えられる |
| 制御可能性 | 手順や時間を利用者が管理でき、中断・取り消しができる |
| 使用エラーへの耐性 | エラーが起きても利用者が自分で回復できる |
| エンゲージメントへの配慮 | 利用者の意欲を保てる |

### 3. 情報提示の原則（JIS Z 8522:2022）

人の認知の特性に合わせて情報を見せる 6 項目。気づきやすさ、注意をそらさないこと、区別しやすさ、解釈しやすさ、簡潔さ、内部・外部の一貫性。

### 4. 人間中心の原則

自律性の高いシステム（AI など）を使うときの配慮として位置づけられている。詳しくはガイドブックの 3.6 節を参照。
