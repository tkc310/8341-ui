# 0018 エージェント向けの文書を必要なときだけ読み込む構成にする

- 日付: 2026-10-21
- 状態: 採用

## 背景
スキルと文書が増え、エージェントが一度に読む量が大きくなっていた。`design-principles` の SKILL.md は 3 つの作業モードの手順とレポートの形をすべて持ち、使わないモードの分まで毎回読まれていた。`ds-factory`・`ds-slides`・`ds-storybook-preview` も、後半の段階や失敗したときにしか要らない内容を本体に持っていた。`ds-build-ui` は 33KB ある DESIGN.md の全文を最初に読む手順だった。スキルの一覧も、ai-agents.md と CONTRIBUTING.md に別々の表があり、`ds-slides` を足したときに片方だけが更新されていた。

## 決定
- 文書を 3 段階に分ける。**0. 常に**（`AGENTS.md` と各スキルの `name`・`description`。索引だけ）、**1. スキルを使うとき**（`SKILL.md` の本体。手順の骨組みだけ）、**2. その段階に入ったとき**（スキルのディレクトリに置いた段階ごとの文書と `docs/` の文書。大きい文書は該当する節だけ）
- `SKILL.md` の本体は空白を除いて 2,000 字以内にする。超えるなら段階ごとの文書に分け、その段階の手順からリンクする
- 入口のスキル（`design-init`・`design-adjust`・`design-review`）は、`design-principles` のモードの文書を指すだけにし、内容を写さない
- スキルの一覧は `docs/skills.md` の 1 か所に置き、README・AGENTS.md・ai-agents.md・CONTRIBUTING からはリンクする
- `AGENTS.md` から文書を自動で読み込む書き方（`@path` の取り込み）は使わない
- `scripts/check-skills.ts` を `make check` で動かし、name とディレクトリの一致、description、一覧の網羅、本体の字数、リンク切れ、どこからも参照されない文書を検査する

## 理由
- エージェントは `description` を見てスキルを選び、選んだときに本体を読む。本体を骨組みにし、詳細をその段階で読ませれば、使わない手順やモードのために読む量が減る
- 段階ごとの文書を同じディレクトリに置けば、Claude Code・Cursor・Codex のどれでも同じ相対パスで読める（`.agents/skills` は `.claude/skills` へのシンボリックリンク）
- 字数の上限と参照の検査を CI に入れると、スキルを足すたびに本体が太る・読まれない文書が残ることを防げる
- 一覧を 1 か所にすれば、スキルを足したときの更新漏れが起きない（一覧への掲載も検査する）

## 影響・トレードオフ
- スキルを使うとき、段階ごとの文書を読むためにファイルを開く回数が 1〜2 回増える
- 段階ごとの文書の冒頭に「いつ読むか」を書き、手順からリンクしないと読まれない（参照されない文書は検査で落ちる）
- 上限の 2,000 字は、分割後の最大（design-principles の約 1,900 字）に合わせた目安。足りなくなったら、上げる前に分け方を見直す
