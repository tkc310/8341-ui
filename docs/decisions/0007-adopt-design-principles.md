# 0007 画面設計のルールに design-principles を採用する

- 日付: 2026-10-18
- 状態: 採用

## 背景

初版のルールブックは独自の 5 原則を置いていた。一方、`tkc310/agents-playground` の `docs/design-principles` に、UI の方向性 → サービス別の特化ルール → 15 の原則 → WCAG 2.2 という、判断の重複しないルール体系がすでにある。二つを並べると、同じ判断が二か所に書かれて食い違う。

## 決定

- 画面設計のルールは design-principles を正とし、tkc310-ui には本文を写さない
- tkc310-ui のルールブック 01 章は、上流の各ルールをどのトークンとコンポーネントで満たすかの対応表にする
- UI の方向性とサービス種別は基盤では決めず、各プロダクトの DESIGN.md で決める（`templates/PRODUCT-DESIGN.md`）
- 独自の原則のうち、システム自体の作り方に関するもの（少ない選択肢、ネイティブ要素優先、測って直す）は「設計方針」として残す
- 上流にギャップを見つけたら、tkc310-ui で例外を作らず上流へ PR を出す

## 理由

ルールの置き場所を一つにすると、更新の漏れと食い違いが起きない。対応表にすることで、上流のルールが変わったときに、どの部品へ影響するかを辿れる。

## 影響・トレードオフ

- 上流が非公開リポジトリのため、tkc310-ui だけを見てもルールの本文は読めない。必要なら上流を公開するか、リリースごとにスナップショットを取り込む
- 初版作成時に見つけたギャップは、上流の PR（tkc310/agents-playground#27）で提案した
