# 0010 Tailwind のテーマ名とトークンの対応

- 日付: 2026-10-18
- 状態: 採用

## 背景

semantic トークンを Tailwind のユーティリティとして使えるようにしたい。一方で Tailwind 既定のパレットや文字サイズが残っていると、トークン外の値が混ざる。

## 決定

- `color.bg.*` → `bg-*`、`color.text.*` → `text-fg-*`、`color.icon.*` → `text-icon-*`、`color.border.*` → `border-border-*` のように、役割ごとに接頭辞を変えて衝突を避ける
- 余白・コントロール寸法は `--spacing-*`（`p-inset-md`、`h-control-md`）、テキストスタイルは `--text-*`（行間・字間・太さを含む）
- `@theme inline` で、値はすべて `var(--tkc-*)` を参照する（テーマ切り替えに追従させるため）。ブレークポイントだけはメディアクエリで var() が使えないため値で書く
- Tailwind 既定の色・文字サイズ・角丸・影・ブレークポイントは `initial` で消す。数値の余白は残す
- 任意値・手書き CSS では `--tkc-*` を参照する（`@theme inline` は使われた変数しか出力しないため）

## 理由

クラス名から役割が読み取れ、間違った組み合わせ（文字色に面の色を使うなど）が目に付く。既定値を消すことで、トークン外の値はそもそも効かなくなる。

## 影響・トレードオフ

- `border-border` のように同じ語が続くクラスがある
- 既定の `text-sm` などに慣れた人は最初に戸惑う。DESIGN.md のクイックリファレンスと、効かないクラスをコンパイルで検出する検証で補う
