# 0017 スライドを HTML のデッキとしてトークンから組む（ds-slides）

- 日付: 2026-10-20
- 状態: 採用

## 背景
8341-ui を使うプロダクトの説明や提案で、発表用のスライドを作る場面がある。スライドを汎用のツールで作ると、色・文字・余白が 8341-ui とずれ、コントラストや色だけの区別などデザイン原則と WCAG の確認もやり直しになる。AI エージェントにスライドを作らせても、同じことが起きる。

## 決定
- スライドは **1 ファイルの HTML のデッキ** として作る。ソース（`section.slide` を並べた HTML）を `scripts/slides/build.ts` が組み立て、CSS・JavaScript・アイコンを埋め込む。印刷すると 1 枚 1 ページの PDF になる
- 見た目は `scripts/slides/deck.css` が **semantic トークンだけ** で決める。CSS 変数は `packages/tokens/scripts/lib/tokens.ts`（Resolver）で解決し、`make tokens` や外部の依存なしで動かす。primitive は出力しない
- キャンバスは **960×540 の論理サイズ（rem）** にし、画面に合わせて全体を拡大・縮小する。スライド専用のトークンは作らず、既存のテキストスタイルを使う（本文 `text.body-lg`、見出し `text.heading-lg`、表紙・章扉 `text.display-md`）
- design-principles の原則をスライドに落としたルールを `docs/rulebook/07-slides.md`（S1〜S20）にまとめ、静的に確かめられるものは `scripts/slides/check.ts` で検査する。`make check` は `deck.css` の監査と見本の検査を行う
- 作者が選べるのはレイアウト（10 種）と決まったクラスだけ。`style` 属性・`<style>`・独自のクラスはエラーにする
- 手順はスキル `ds-slides` にまとめる

## 理由
- HTML ならトークン（CSS 変数）をそのまま使え、テーマの切り替えも `contrast.rules.json` の検証結果もそのまま効く。.pptx などに変換すると、トークンとの対応と検証が切れる
- 960×540 で 18px の本文は、1920 幅の画面では 36px 相当になり、投影で読める大きさを既存のトークンで満たせる。寸法を rem にしたので、利用者の文字サイズ設定ごと全体が拡大する
- 幅 768px 未満と印刷では 1 枚ずつ縦に並べる「一覧」にし、拡大・縮小で文字が小さくなりすぎないようにした（WCAG 1.4.10・1.4.4）
- 作者に色や寸法を選ばせないことで、エージェントが作っても原則とコントラストから外れない

## 影響・トレードオフ
- 発表者ビュー（次のスライドとメモを並べる画面）は無い。メモは一覧モードで読む
- PowerPoint や Google スライドで編集したい場合は、この仕組みの外になる（必要になったらバックログで検討する）
- ソースは整った HTML を前提にした簡易な解析で読む。閉じタグの抜けはエラーにする
- 使えるクラスやレイアウトを増やすときは、`lib.ts`・`deck.css`・07 章・見本を同時に直す
