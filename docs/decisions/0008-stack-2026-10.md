# 0008 技術スタックを Base UI + Tailwind v4 + shadcn 方式に移行する

- 日付: 2026-10-18
- 状態: 採用（0001 を置き換える）

## 背景

初版は React + プレーン CSS（BEM + data 属性）で、振る舞いはネイティブ要素に頼っていた。利用先のプロジェクトは Tailwind CSS と shadcn/ui の組み合わせが主流になり、ヘッドレス UI の上で見た目だけを持つ方が、利用側での改変と保守が楽になる。

## 決定

| 役割                 | 採用                                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| ヘッドレス UI        | Base UI v1（`@base-ui/react`）                                                                                                                    |
| 配布                 | shadcn 方式（コードを持つ）＋独自レジストリ（`registry:base` で Base UI を固定）。npm パッケージ（ESM のみ・exports・型・CSS は別エントリ）も出す |
| スタイル             | Tailwind CSS v4 ＋ CSS 変数。ダークは `.dark` / `[data-theme]`（どちらも無ければ OS 追従）                                                        |
| バリアント           | tailwind-variants v3（クラス統合は内蔵。tailwind-merge は不要）                                                                                   |
| RSC                  | フック・コンテキスト・イベントハンドラを作るエントリだけ `'use client'`                                                                           |
| トークン             | W3C DTCG 2025.10 → Style Dictionary v5 → CSS 変数・Tailwind `@theme`                                                                              |
| Figma                | Variables（DTCG JSON）＋ Code Connect テンプレート形式（`.figma.ts`）                                                                             |
| ツールチェーン       | Vite+（`vp check` = oxlint ＋ oxfmt、`vp test` = Vitest 5、`vp pack` = tsdown、`vp run` = Vite Task）。lint 設定はルートの `vite.config.ts`       |
| パッケージ管理       | pnpm 11（workspaces / catalog）                                                                                                                   |
| リリース             | Changesets v3                                                                                                                                     |
| アーキテクチャ       | dependency-cruiser                                                                                                                                |
| ドキュメント・テスト | Storybook 10（10.6.1 以上）、Vitest ＋ RTL ＋ happy-dom、addon-vitest、addon-a11y、VRT（toMatchScreenshot、手動）、e2e（Playwright、手動）        |

使わないもの: bun（publish 時の `workspace:` / `catalog:` 解決に既知の不具合。スクリプト実行だけなら可）、tsup（保守終了）、unbuild（2025-08 以降更新なし）、npm の `cva`（0.0.0 の予約。使うなら class-variance-authority）、ESLint / Prettier（oxlint / oxfmt に統一）。

## 理由

- Base UI は Radix の作者が関わり MUI が保守している。v1 で API が安定し、shadcn の既定にもなった（2026-07）
- shadcn 方式なら、利用側はコードを持って改変でき、更新は差分で取り込める。レジストリの `registry:base` で Base UI に固定できる
- Vite+ に寄せると lint・fmt・テスト・ビルド・タスク実行の設定が 1 つの `vite.config.ts` にまとまる

## 影響・トレードオフ

- **Base UI は `data-focus-visible` を付けない**。フォーカス表示は `:focus-visible` で描く（`focus-ring`）
- **tailwind-variants のクラス統合は独自のテーマ名を知らない**。登録しないと `text-fg text-body-md` の文字色が消える。トークンから設定を生成する（`tw-merge-config.ts`）
- **Tailwind の `@theme inline` は使われた変数しか出力しない**。任意値と手書き CSS は `--8341-*` を参照する（[0010](./0010-tailwind-theme-mapping.md)）
- **Storybook 10 を Vite+ の上で動かす方法は公式に記載が無い**。Storybook が対応する Vite の範囲に Vite+ 同梱の Vite 8.3 が入るため動く見込みだが、問題が出たら Storybook だけ素の Vite に戻す
- **pnpm 12 が 2026-08 に出ている**。11 の保守期間を確認し、必要なら上げる
- **shadcn の `registry:base` の書き方はドキュメントと JSON スキーマで食い違う**。CLI で受け付けられる形を確かめて直す。サードパーティのレジストリで `{style}` が置き換わらない不具合（shadcn-ui/ui#10496）があるため、URL に `{style}` を使わない
- Base UI の Select はネイティブの `select` ではないため、モバイルでの操作感が変わる。選択肢が少ないときは RadioGroup を使う規約は維持する
