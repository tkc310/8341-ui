### UI の方向性

- ドメインが専門的であり、対象ユーザーがそのドメインに習熟している場合は、オブジェクト指向 UI を採用する。専門家は対象と操作の関係をすでに知っているため、対象から操作を選ぶほうが速い。
- ドメインが日常的である場合は、オブジェクト指向 UI を採用する。利用者はドメインの対象を日常の知識から理解できる。
- ドメインが専門的であり、対象ユーザーがそのドメインに習熟していない場合は、タスク指向 UI を採用する。専門的な対象を前提知識なしに操作させるには、典型的な手順をシステムが示す必要がある。

### ウェブデザインの原則（必須）

#### 読み順と優先度

どれを先に気づかせ、どの順で読ませるか。

- その画面で最初に伝える要素を、サイズ、位置、色のいずれかで他より先に気づく状態にする。
- 見出しの段（大見出し、中見出し、小見出し）ごとに、見た目の差を付ける。同じ段には同じ見た目を使う。
- 一つだけ強調する要素は、周囲と違う見た目にする。強調は画面につき少数にとどめる。

#### まとまり

同一画面の中で、どれとどれを一つのグループに見せるか。

- 関係する要素（ラベルと入力欄、見出しと本文）の間隔を、関係しない要素の間隔より狭くする。
- グループの境は、余白、枠、背景のいずれかか、その組み合わせで分かるようにする。
- 同じグループに属する要素は、色、形、サイズを揃える。違うグループは、そのいずれかで区別する。
- 手順や時系列は、線や並びに沿って一つの連なりに見えるようにする。

#### 文字と図の判別

文字と、情報を伝える図が判別できるか。

- 通常サイズの文字と背景のコントラスト比は 4.5:1 以上、大きい文字は 3:1 以上にする。プレースホルダーも文字である。
- 情報を伝えるアイコン、グラフ、入力欄の境界と、隣接する色とのコントラスト比は 3:1 以上にする。
- 色だけで状態や系列を区別しない。形、ラベル、パターンのいずれかを併用する。
- 本文の文字サイズと行間は、デザインシステムに一つの初期値として定め、画面ごとに縮めない。
- コンテナの内側には余白を置き、文字が枠に接触しないようにする。

#### 配置の秩序

位置が基準線に乗り、画面の視覚的な重さが極端に偏らないか。

- 関係する要素群を、左、中央、右のいずれかの基準線で揃える。
- 列の幅と列間は、画面内で同じグリッドに乗せる。
- 主内容と副内容を並べるとき、幅の比を画面内で一定にする。

#### 操作の幾何

押せるものの大きさと、隣との距離。

- ポインタで操作する対象は、一辺 24 CSS ピクセル以上にする。満たさない対象は、各対象のバウンディングボックスの中心に置いた直径 24 CSS ピクセルの円が、他の対象やその円と交差しない位置に置く。
- 同じ画面で続けて押す操作は、直前に操作する要素（入力欄、選択した行など）の近くに置く。

#### 一度に出す数

同時に選ばせる個数。

- 一つの決定に、画面いっぱいの並列選択肢を出さない。分類、段階的な開示、既定値のいずれかで個数を減らす。
- 長い一覧は、見出し、ページ分割、絞り込みのいずれかでまとまりに分ける。

#### 一貫性

画面をまたいで同じ機能を同じものに見せるか。ウェブで広く使われている配置を崩さないか。

- 保存、取消、削除のように同じ機能のボタンは、全画面で同じ見た目とラベルにする。
- 色の意味（リンク、エラー、成功）を画面ごとに変えない。
- ナビゲーションの位置と項目の順を、全ページで変えない。
- ロゴの位置、戻る操作、主要なメニューの置き方は、他のウェブサイトで広く使われている配置から外れる理由があるときだけ変える。利用者は他サイトで過ごす時間のほうが長く、そちらの配置を前提に操作する、という観察がジャコブの法則と呼ばれる。

#### 状態と応答

今何が起きているか。待ちが長いか。

- 操作を受け付けたこと、処理中であること、完了または失敗したことを、それぞれ画面に表示する。
- 応答がすぐ終わらない処理には、待っていることが分かる表示を出す。
- ナビゲーションでは、現在のページがどこかを表示する。
- 自動で動くカルーセルや通知は、利用者が止められるようにする。条件は wcag-for-designers.md（`docs/design-principles/wcag-for-designers.md`） の 2.2.2 に従う。

#### 誤りと撤回

失敗を防ぐか。失敗の内容と戻り方を示すか。操作を中断できるか。

- 削除や送信など取り消せない操作の前に、内容を確認する段階を置く。
- 入力の形式と制約（必須か、文字数、使える文字）を、入力する前に示す。
- エラーが起きた項目と、利用者が自分で直せる方法を示す。番号だけのエラーにしない。
- モーダルと複数段の入力には、閉じる、中断する、下書きを残すのいずれかを置く。
- 時間制限を置く場合は、解除、調整、延長のいずれかを利用者ができるようにする。条件と例外は wcag-for-designers.md（`docs/design-principles/wcag-for-designers.md`） の 2.2.1 に従う。

#### 再認

思い出させず、見せて選ばせるか。

- 入力値の候補があるときは、自由入力だけにせず候補を出す。
- 直前までに入力した値を、後の段で再入力させない。セキュリティ上必要な再入力と、無効になった値は除く。
- アイコンだけの操作には、ラベルかツールチップで名前を添える。

#### 文言

ラベルと文が、操作の結果と入力の意味を言うか。

- ボタンとリンクのラベルに、移動先か動作が入るようにする。「こちら」「詳細」「もっと見る」だけにしない。
- 入力欄には、何を入れるかのラベルを付ける。形式の指定（日付の並びなど）は、エラーのあとではなく前に書く。
- エラー文には、何が違うかと、どう直すかを書く。
- 利用者の作業用語を使い、画面の実装用語をラベルに出さない。

#### 削る

その画面の主タスクに不要な要素を置かないか。レイアウトで伝わることを文字で繰り返さないか。

- その画面の主タスク（利用者がその画面で終えたい作業）に使わない装飾、説明、動く要素を置かない。
- 見出し、配置、まとまりで既に伝わることを、セカンダリラベル（小見出し、見出しの上の補助ラベル、項目名の前置き）や説明文で繰り返さない。例: 入力欄のラベルを言い換えただけの補足文、ページの見出しを言い直すだけの導入文、カードの中の「詳細」「情報」だけの小見出し、表の列見出しと同じ語を各セルに付けた前置き。
- 項目どうしの関係（どれが同じグループか、どれが主でどれが従か）は、レイアウト（近さ、並び、枠や背景、大きさの差）で示す。関係を説明する文を足して補わない。
- 削ってよいのは重複している表示だけである。入力欄の見えるラベル（WCAG 3.3.2）、見出しや表の見出しセルなど構造を表す要素（1.3.1）、アイコンだけの操作の名前は残す。見た目で示したグループには、読み上げでも取り出せる名前（`fieldset` と `legend`、区画の見出しなど）を付ける。
- 主タスクを遮るポップアップは、利用者の判断が要る場合（未保存の変更の破棄など）に限る。それ以外の通知は、主タスクを遮らない位置に出す。
- 自動で再生・移動する要素は、主タスクの妨げになる場合は初期状態で動かさない。

#### 助けの場所

ヘルプと検索を、サイト内の同じ場所に置くか。

- ヘルプ、検索、問い合わせを置くときは、全ページで同じ位置に置く。WCAG 3.2.6 が求めるのは、ほかの要素に対する相対的な順序を変えないことである。
- ヘルプの項目は、操作の名前で探せるようにする。
- 目的のページへ到達する手段を、ナビゲーション以外にもう一つ置く。検索、サイトマップ、一覧のいずれでもよい。手続きの途中の段や、手続きの結果として表示するページは除く。手段の組み合わせは wcag-for-designers.md（`docs/design-principles/wcag-for-designers.md`） の 2.4.5 に従う。

#### 短い経路

繰り返す操作に、より短い別経路があるか。

- 基本の経路（ボタンを順に押す）を残したうえで、繰り返す操作にショートカット、一括操作、検索のいずれかがある。
- キーボードだけで基本の経路を完了できるようにする。詳細は wcag-for-designers.md（`docs/design-principles/wcag-for-designers.md`） の 2.1.1 に従う。

#### 自律的な処理の範囲

人の操作を待たずに進む処理の境界が分かるか。

- 自動で進んだ処理について、何を根拠に何をしたかを画面上で示す。
- 利用者が止められる地点と、結果を取り消せる地点を置く。
- 人とシステムのどちらが最終決定を持つかを、その画面に書く。
